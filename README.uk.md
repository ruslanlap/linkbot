# LinkBot

[English](README.md) | Українська | [简体中文](README.zh-CN.md)

LinkBot знаходить постійні перенаправлення посилань у Markdown і пропонує зміни через pull request.

> **Експериментальний прототип.** Публічний GitHub App не зареєстровано й не розгорнуто; кнопки встановлення немає. Роботу з реальним GitHub API та створення PR не перевірено. Не використовуйте для production.

## Як користуватися

1. Для експерименту зареєструйте власний GitHub App, розгорніть сервер і надайте доступ до вибраних репозиторіїв. Інструкція конфігурації — в [English README](README.md).
2. Вебхук встановлення запускає сканування. Для щотижневих перевірок окремо запустіть планувальник і вручну задайте `LINKBOT_INSTALLATION_IDS`.
3. Якщо знайдено перенаправлення, перевірте запропонований PR перед злиттям. Якщо гілка `linkbot/permanent-redirects` вже існує, репозиторій пропускається; бот не оновлює її.

**404 без виправлень не створюють повідомлення або PR.** Якщо PR відсутній, це не означає, що всі посилання працюють.

## Альтернатива: GitHub Actions

Скопіюйте `linkbot.py` та `.github/workflows/linkbot.yml` у свій репозиторій. Увімкніть створення PR у налаштуваннях GitHub Actions. Запуск: **Actions → LinkBot → Run workflow**. Цей спосіб не є встановленням GitHub App; workflow ще не перевірено на реальному GitHub.

## Межі

Перевіряються прості HTTPS-посилання в Markdown і лише перенаправлення 301/308 на той самий хост. Зображення, запити URL, блоки коду та частина синтаксису Markdown пропускаються. Якорі зберігаються, але не перевіряються. Перенаправлення не гарантує рівноцінності сторінок; перевіряйте diff вручну.

## Локально

`python3 linkbot.py .` перевіряє і **змінює** Markdown-файли в поточному каталозі; перегляньте зміни перед комітом. Залежності сервера: `pip install -r requirements.txt`. Тести додатково потребують pytest і pytest-subtests: `python3 -m pytest -q`.
