# LinkBot

[English](README.md) | Українська | [简体中文](README.zh-CN.md)

Перевірка HTTPS-посилань Markdown на постійні перенаправлення та 404. CLI, pre-commit і action типово не змінюють файли; `--fix` явно змінює локальні файли. Виконуються HTTPS GET-запити, мережевих записів немає.

## CLI

Потрібен Python 3.9+ і pip; основний код не має сторонніх залежностей:

```sh
python3 -m pip install .
linkbot
linkbot docs README.md
linkbot --fix docs
```

Перевіряйте diff. Код виходу: 0 — без знахідок (або виправлено і немає 404), 1 — перенаправлення в режимі перевірки або 404, 2 — помилка аргументів чи читання/запису. Мережеві помилки й непідтримувані посилання пропускаються: успіх не гарантує працездатності всіх посилань. Вивід містить кількість змінених посилань, файли та 404. При помилці пізнішого файлу попередні зміни можуть залишитися.

## pre-commit

Встановіть [pre-commit](https://pre-commit.com/), додайте `.pre-commit-config.yaml`, приклад закріплено на опублікованій версії:

```yaml
repos:
  - repo: https://github.com/ruslanlap/linkbot
    rev: v0.1.0
    hooks:
      - id: linkbot
```

Виконайте `pre-commit install` та `pre-commit run --all-files`. Хук перевіряє передані Markdown-файли, не редагує їх та індекс Git, зокрема частково staged файли. Виправляйте окремо через `linkbot --fix`, перевіряйте та додавайте зміни вручну. Мережеві перевірки можуть бути повільними або неповними офлайн.

## GitHub Action

Потрібні checkout, Python 3 і bash. Приклад закріплено на опублікованій версії:

```yaml
jobs:
  links:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v4
      - id: links
        uses: ruslanlap/linkbot@v0.1.0
        with:
          path: docs
```

`path` — файл або каталог, типово `.`. Новий параметр `fix` приймає лише `'true'` або `'false'` (типово); `'true'` застосовує допустимі виправлення. Вихід `exit-code` дорівнює 0, 1 чи 2; крок завершується помилкою при 1 і 2. Читати через `${{ steps.links.outputs.exit-code }}`; після помилки використовуйте `if: always()` або `continue-on-error`. Action не потребує токена чи прав на запис і не створює PR.

### Заплановані PR з виправленнями

Скопіюйте [`.github/workflows/linkbot.yml`](.github/workflows/linkbot.yml) у свій репозиторій за тим самим шляхом. Він запускається щотижня або вручну, викликає опублікований action з `fix: 'true'` та групує зміни в одному PR через `peter-evans/create-pull-request`. Код 1 дозволяє створити PR за наявності невиправлених 404; код 2 або відсутній статус блокує PR. Самі лише 404 не створюють PR; переглядайте журнал action. Перевіряйте виправлення перед злиттям. Workflow надає лише права contents і pull-requests на запис; налаштування репозиторію також мають дозволяти Actions створювати PR.

Workflow посилається на `@main`: спочатку ці зміни треба злити й опублікувати. Після публікації зафіксуйте незмінний commit або реліз із `fix`; наведений вище приклад `v0.1.0` лише перевіряє посилання. Реальний PR не перевірено.

## Межі

Підтримуються прості inline HTTPS-посилання Markdown, посилання-значки із зображенням та однорядкові HTML-якорі з лапками навколо href. Джерела зображень, URL із query, блоки коду та рядки з backtick або зворотною косою рискою пропускаються. Виправляються 301/308 на той самий хост, що закінчуються 200. Для підтвердженого 404 `releases/latest/download` використовується публічний GitHub API без токена: виправлення можливе лише для єдиного збігу імені asset, що відрізняється стабільною версією релізу. Неоднозначні, відсутні, чернеткові та prerelease релізи не виправляються; ліміт API може завадити. Якорі зберігаються, але не перевіряються; приватні адреси відхиляються. Деякі HTTP/мережеві помилки та недоступні каталоги не виявляються. Перевіряйте кожну зміну; не додавайте секрети в URL.

Експериментальний код розміщеного GitHub App у `ghapp/` збережено, але він не підтримується.

Для повного набору тестів встановіть `requirements.txt`, `pytest`, `pytest-subtests`, `pyyaml` і запустіть `python3 -m pytest -q`.
